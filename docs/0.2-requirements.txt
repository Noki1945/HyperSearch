# HyperSearch 0.2 — Liquid Glass, Spotlight Search, оптимизация и анализ хранилища

Ты — опытный Rust-разработчик, специалист по Windows 11, файловым системам NTFS, высокопроизводительному поиску, нативным интерфейсам и оптимизации оперативной памяти.

Твоя задача — существенно улучшить существующий проект HyperSearch:

https://github.com/Noki1945/HyperSearch

**Не создавай новый проект.** Работай с существующим репозиторием, сохраняя его поисковый движок, совместимость и уже реализованные функции.

Основная цель — создать очень быстрый, удобный и визуально современный файловый менеджер для Windows с интерфейсом в стиле macOS Tahoe Liquid Glass.

Дополнительная цель — дать пользователю удобный способ оценить использование дискового пространства и экспортировать структуру файлов для анализа искусственным интеллектом.

# 10. Интеграция WinDirStat

Добавь в настройки HyperSearch новый раздел:

**Хранилище → Анализ диска**

Здесь пользователь сможет быстро получить доступ к WinDirStat.

WinDirStat — сторонняя программа с открытым исходным кодом для анализа использования дискового пространства.

Официальный репозиторий:

https://github.com/windirstat/windirstat

### Основные требования

Не копируй визуализацию WinDirStat.

Не реализуй собственный Treemap.

Не встраивай исходный код WinDirStat внутрь HyperSearch.

Вместо этого создай удобную интеграцию с внешним приложением.

### Интерфейс

В разделе настроек покажи:

**WinDirStat**

Описание:

«Анализ занятого пространства на дисках. Помогает найти большие файлы и папки».

Кнопки зависят от состояния программы.

Если WinDirStat не установлен:

- «Скачать и установить».
- «Открыть официальный сайт».

Если WinDirStat установлен:

- «Открыть WinDirStat».
- «Проверить обновления».

### Поиск установленной программы

Сначала проверяй, установлен ли WinDirStat.

Используй стандартные механизмы обнаружения Windows:

- Записи установленных приложений.
- Официальные записи реестра.
- Стандартные пути установки.

Не сканируй весь диск при каждом открытии настроек.

Если обнаружить программу не удалось, разреши пользователю вручную указать путь к исполняемому файлу.

### Автоматическое скачивание

При нажатии «Скачать и установить»:

1. Получи сведения об актуальном официальном релизе WinDirStat.
2. Найди подходящий установочный пакет для Windows.
3. Проверь источник загрузки.
4. Скачай пакет во временный каталог.
5. Проверь доступную цифровую подпись и опубликованную контрольную сумму, если они предоставлены.
6. Если подлинность пакета не удаётся установить надёжно, предложи открыть официальную страницу загрузки вместо автоматического запуска.
7. Покажи пользователю название и источник пакета.
8. После подтверждения пользователя запусти стандартный установщик Windows.
9. Если требуется UAC, используй штатный механизм Windows.
10. После установки повторно проверь наличие программы.

Не используй сторонние сайты для загрузки.

Не выполняй тихую установку без согласия пользователя.

Не отключай Windows Defender или SmartScreen.

Не требуй прав администратора для самого HyperSearch только ради интеграции.

Если автоматическая загрузка недоступна, открывай официальную страницу релизов.

### Запуск WinDirStat

При нажатии «Открыть WinDirStat» запускай установленное приложение.

Если программа отсутствует, предложи установить её.

Не запускай WinDirStat автоматически при каждом запуске HyperSearch.

### Дополнительная возможность

Добавь кнопку:

«Анализировать этот диск в WinDirStat».

Она должна быть доступна в контекстном меню диска.

Если WinDirStat поддерживает документированный аргумент для открытия выбранного диска, используй его.

Не придумывай неподтверждённые аргументы командной строки.

# 11. Экспорт структуры хранилища для анализа ИИ

Это одна из важнейших новых функций.

Пользователь должен иметь возможность получить подробный отчёт о том, как заполнен его диск.

Цель — экспортировать информацию о файлах и папках в структурированном формате, чтобы её можно было передать ChatGPT, Claude или другой нейросети для анализа.

Пример пользовательского сценария:

1. Пользователь открывает HyperSearch.
2. Переходит в настройки.
3. Выбирает «Анализ хранилища».
4. Нажимает «Экспортировать структуру диска».
5. Выбирает диск C:.
6. Программа собирает необходимые метаданные.
7. Создаёт отчёт.
8. Пользователь отправляет отчёт нейросети.
9. Нейросеть помогает выявить потенциально ненужные файлы и папки.

### 11.1. Какие данные экспортировать

Для каждого объекта, если данные доступны:

- Имя файла или папки.
- Полный путь.
- Тип объекта.
- Расширение.
- Логический размер файла в байтах.
- Выделенный размер на диске, если его можно корректно определить.
- Дата последнего изменения.
- Дата создания, если доступна.
- Родительский каталог.
- Уровень вложенности.
- Атрибуты файла.
- Признак символической ссылки или reparse point.

Для папок:

- Суммарный логический размер вложенных файлов.
- Количество вложенных файлов.
- Количество вложенных папок.
- Доля от общего анализируемого объёма.

Не путай логический размер с физически занятым пространством.

Учитывай, что hard links, sparse files, сжатие NTFS и reparse points могут приводить к двойному подсчёту или различиям между логическим и физическим размером.

Документируй метод подсчёта.

### 11.2. Производительность сканирования

Используй существующий индекс HyperSearch для получения структуры и имён объектов.

Но учитывай, что текущий поисковый индекс не содержит всех необходимых метаданных о размерах файлов.

Добавь отдельный модуль анализа хранилища.

Для получения размеров используй эффективные документированные Windows API.

По возможности:

- Не открывай содержимое файлов.
- Не читай каждый файл целиком.
- Не вычисляй хеш каждого файла.
- Не загружай все метаданные в RAM.
- Обрабатывай записи потоково.
- Используй ограниченные буферы.
- Позволяй отменять сканирование.

Не обходи junctions и символические ссылки рекурсивно без специального разрешения.

Не допускай бесконечных циклов.

Сканирование не должно блокировать интерфейс.

### 11.3. Форматы экспорта

Поддержи три формата.

**JSON**

Полный структурированный отчёт для программной обработки и ИИ.

**CSV**

Табличный формат, который можно открыть в Excel.

**TXT / Markdown**

Читаемый отчёт, удобный для передачи нейросети.

Пример структуры:

C:
  Users
    User
      Downloads\ — 24.8 GB
      Documents\ — 8.2 GB
      Pictures\ — 15.4 GB
  Windows\ — 32.1 GB
  Program Files\ — 48.6 GB
  Program Files (x86)\ — 12.3 GB

Это исключительно пример формата, а не реальные данные пользователя.

### 11.4. Сводка для нейросети

Помимо полного экспорта создавай компактный аналитический отчёт.

Он должен содержать:

- Общий размер анализируемого хранилища.
- Занятое пространство.
- Свободное пространство.
- Количество файлов.
- Количество папок.
- Топ-100 крупнейших файлов.
- Топ-100 крупнейших каталогов.
- Распределение по расширениям.
- Распределение по категориям.
- Старые крупные файлы.
- Большие временные каталоги.
- Потенциальные дубликаты, только если они подтверждены надёжным методом.

Отдельно выделяй потенциальные кандидаты на очистку.

Например:

- Старые установщики.
- Большие файлы в Downloads.
- Старые архивы.
- Временные файлы приложений.
- Крупные логи.
- Старые резервные копии.
- Неиспользуемые пользовательские ISO-образы.

Это должны быть кандидаты на проверку, а не автоматически признанный мусор.

### 11.5. Безопасность рекомендаций

Очень важно.

HyperSearch не должен самостоятельно удалять файлы на основании отчёта.

Не классифицируй системные файлы как безопасные для удаления только из-за их размера или возраста.

Особенно осторожно обрабатывай:

- C:\Windows
- C:\Windows\WinSxS
- C:\Windows\System32
- C:\Program Files
- C:\Program Files (x86)
- C:\ProgramData
- AppData
- Windows.old
- pagefile.sys
- hiberfil.sys
- System Volume Information

Для таких объектов выводи пояснения.

Например, Windows.old может удаляться через штатные средства очистки Windows, но не должен удаляться простым ручным удалением файлов без проверки состояния системы.

Для установленных программ рекомендуй штатную деинсталляцию.

Не выдавай рекомендации, которые могут повредить Windows.

### 11.6. Приватность экспорта

Полные пути могут содержать:

- Имена пользователей.
- Названия личных документов.
- Рабочие проекты.
- Конфиденциальные названия каталогов.

Поэтому добавь два режима экспорта.

**Полный отчёт**

Содержит реальные имена и пути.

**Безопасный отчёт для ИИ**

По умолчанию скрывает имя пользователя и позволяет исключить выбранные каталоги.

Например:

C:\Users\USERNAME\Documents\...

Для чувствительных каталогов предусмотрена возможность заменить названия нейтральными идентификаторами.

Перед экспортом показывай предварительный просмотр.

Предупреждай, что отчёт может содержать личную информацию.

Ничего автоматически не отправляй в интернет.

Не подключай внешние ИИ API без отдельного согласия пользователя.

### 11.7. Отчёт для ChatGPT

Добавь кнопку:

«Создать отчёт для ИИ».

Она должна:

1. Собрать сводную статистику.
2. Выделить наиболее значимые каталоги.
3. Сформировать компактный Markdown-отчёт.
4. Добавить пояснение о методике расчёта.
5. Добавить предупреждения о неполных данных.
6. Сохранить отчёт на компьютер.

Также добавь кнопку «Скопировать запрос для ИИ».

Пример автоматически создаваемого запроса:

«Проанализируй приложенный отчёт о файловой системе Windows. Найди крупные каталоги и файлы, которые потенциально можно очистить. Раздели рекомендации на безопасные, требующие проверки и системные объекты, которые нельзя удалять вручную. Оцени возможную экономию места без двойного подсчёта вложенных каталогов. Не предлагай удаление системных файлов без штатной процедуры Windows. Для каждой рекомендации объясни риски и способ проверки».

Не отправляй отчёт автоматически.

### 11.8. Работа с очень большими дисками

Отчёт по миллионам файлов может быть слишком большим для нейросети.

Поэтому реализуй:

- Полный экспорт.
- Компактный экспорт.
- Экспорт выбранного каталога.
- Ограничение глубины вложенности.
- Настраиваемый минимальный размер объектов.
- Топ крупнейших файлов.
- Агрегацию мелких объектов по каталогам.

Не обрезай отчёт молча.

Показывай количество пропущенных или агрегированных записей.

При необходимости разбивай полный отчёт на части.

В компактном отчёте сохраняй достаточно информации для оценки использования хранилища.

## 14. Требования к производительности

Главное правило: новые функции не должны ухудшать скорость поиска без обоснованной причины.

Требования:

- Минимальная CPU-нагрузка в простое.
- Отсутствие постоянной перерисовки неподвижного UI.
- Аппаратное ускорение, где оно оправдано.
- Асинхронная загрузка иконок.
- Виртуализация списков.
- Ограниченные кэши.
- Отсутствие блокировки UI-потока.
- Отсутствие повторной индексации без необходимости.

Анализ размеров файлов должен запускаться отдельно от обычного поиска.

Не собирай все размеры файлов при каждом запуске HyperSearch.

Не добавляй постоянную фоновую нагрузку ради отчётов, которые пользователь запускает редко.

Измеряй расход памяти поискового движка, интерфейса и анализатора хранилища отдельно.
