# HyperSearch 0.2 — work plan

Work starts from beta commit e1ebc4678425c80cd2fafa089dfb8532cb2310f8. No 0.2 release may be published without the owner's confirmation. Screen capture stays off.

The existing modules have stable ID cursors, three memory profiles, portable derived caches and a native Win32 GUI. Keep their contracts. Main gaps: the UI is not virtualized, settings live in the main window, there is no global palette or storage exporter, and monitor batches reconstruct FRN lookup. The complete request is saved in 0.2-requirements.txt.

Baseline: benchmarks/0.2-baseline.txt, plus the existing MEMORY_MODES, VALIDATION, CACHE, PERFORMANCE and BETA_TEST_REPORT documents. Comparisons must distinguish process startup, engine readiness, queries and metadata analysis.

Stages: audit; native composition/appearance and virtual view; global search palette; RAM details; filters/ranking/metadata; persistent WinDirStat discovery; cancellable storage metadata scan; streaming exports; privacy/AI summary; incremental monitoring/startup; final tests/docs. Commit independently after each working stage and run workspace tests, formatting, Clippy and a release build. Incomplete stages must remain explicitly incomplete.

DWM system backdrops support Windows 11 build 22621 onward; provide an opaque fallback. Direct2D/Composition offer more rendering control but are not prerequisites for basic native controls; no browser runtime is justified. Animations must be event-driven, never a perpetual repaint loop.

WinDirStat detection must validate remembered paths on every settings open and check registry/standard locations when missing. Only launch on an explicit click. If automatic package authenticity cannot be verified, use the official releases page rather than executing an unverified download. Never automatically install tools during development or on application startup.
