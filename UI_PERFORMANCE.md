# HyperSearch 0.2 UI and performance

Native Rust/Win32, without a browser runtime. The design is Liquid Glass inspired and uses Windows materials, not Apple resources. Main/settings windows request rounded DWM Mica surfaces; Spotlight requests desktop Acrylic. Unsupported DWM attributes fall back to an opaque surface. Light/dark/system, transparency and an optional short Spotlight appearance animation are persisted. There is no decorative frame loop.

Direct2D supports accelerated drawing and DirectComposition supports retained composition/animation. A custom scene would duplicate native control layout/accessibility work; this version chooses the smaller DWM + GDI/native-control implementation. References: [Direct2D](https://learn.microsoft.com/en-us/windows/win32/direct2d/direct2d-overview), [DirectComposition](https://learn.microsoft.com/en-us/windows/win32/directcomp/directcomposition-portal), [system backdrops](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type), [extended glass frames](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe).

The main window provides back/forward/up, address, Known Folder favorites (including redirected OneDrive paths), disks, recent files and persistent pins. Details/list/icon views share an owner-data virtual list, native multiple selection, context actions and copying selected paths. Column sorting and relevance ranking operate on loaded pages, preserving engine ID cursors; they do not promise a global sort of every match.

Filters support categories, comma-separated extensions and in:"C:\Work Files". Optional rank:on orders a bounded page by exact/prefix/word-prefix/substring relevance and opening frequency. Core search ordering stays unchanged. Metadata and shell type icons use independent workers; type icons are capped at 256, opening history at 1,000. Type icons use attributes/associations rather than extracting icons from each matching executable/image.

Settings have seven separate sections: Appearance, Search, Indexing, Storage, Shortcuts, Performance, About. Spotlight shares the loaded index and cancellation mechanism, opens on the active screen and supports arrows/Enter/Escape/Ctrl+C. It never rescans the filesystem. Global hotkeys default to off; explicit registration detects conflicts and preserves the prior combination after invalid input or a registration failure. See [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).

USN is checked every three seconds without a busy loop. Persistent FRN lookups and incremental posting updates avoid rebuilding search tables for small changes. Metadata-only notifications do not refresh visible results. Access failure/journal gap disables polling until reload and leaves a freshness warning. A running export holds a consistent shared index and temporarily defers index mutations. Directory-walk snapshots need explicit rebuild. The disk snapshot/checkpoint is caught up at startup; in-session table changes are not rewritten to disk on each notification.

The first-run screen estimates all three profiles, shows total/available system RAM and object counts, and supports a target budget. Complete search tables are not loaded before a choice. Repeated launches honor saved settings and the checked table cache.

## Validation and limits

Measured on the preserved 1,281,006-object snapshot: GUI application-ready 1314.421 ms, request-to-model 2.286 ms for a substring excel.exe request (four rows). GUI private RAM at readiness: 481,898,496 bytes (459.6 MiB). The separately measured fast CLI engine process used 458.2 MiB private RAM. These are separate process observations, not an exact subtraction attributing all memory to controls. An earlier diagnostic overlapped a standalone metadata-export process; the final repeat is in benchmarks/0.2-gui-final.txt. 9.993 seconds of hidden idle produced 0.000000 additional process CPU seconds at the Windows counter's resolution; this is not a visible-window GPU measurement. See the recorded smoke log.

The hidden --self-test-ui diagnostic runs the real application message/worker pipeline without showing windows or capturing the screen. HYPERSEARCH_UI_REPORT chooses its local output. It checks virtual/multiple-selection styles, separate windows, section visibility, theme application, results and asynchronous metadata/error handling. See benchmarks/0.2-gui-final.txt and the earlier 0.2-gui-smoke.txt. Its timing is request-to-model, not keystroke-to-photon latency.

Native tests additionally cover Unicode owner-data callbacks, bounded buffers, navigation/selection, real hotkey registration/conflict/unregistration and system type icons. Geometry tests cover 96/120/144/192 DPI, small work areas and secondary monitors with negative coordinates. Per-monitor v2 awareness, scaled fonts/geometry and DPI-change rectangles are implemented. This machine has one monitor at 96 DPI. Physical mixed-DPI/multi-monitor presentation, visual fidelity, GPU traces and screen-reader behavior have not been visually validated. Screen capture remains disabled. Some native controls retain system-theme details.

Reproduce core timings with hypersearch-cli audit --memory fast|balanced|economy --iterations 100. This reads a snapshot without asserting freshness, includes path reconstruction, and performs only in-memory rename experiments. See benchmarks/0.2-fast.txt, 0.2-balanced.txt, 0.2-economy.txt and the earlier 0.2-baseline.txt. Measurements use a warm OS cache on one PC; they are not guarantees for every query/disk. The earlier Explorer comparison remains in VALIDATION.md and does not establish a universal speedup factor.

Appearance also provides saved 90/100/110/120 percent text sizing. The information pane can be hidden with its toolbar button. Spotlight includes file types and a location button and dismisses after opening a result. RAM estimates include separate file/folder counts and explanations of each mode.

Indexing settings show USN freshness, last applied update and saved absolute-path exclusions. Excluded files are removed before saving the snapshot; directory anchors remain for USN parent links but are hidden from search and inherited export scope. A directory crossing an exclusion boundary requires explicit rebuilding; polling stops with a stale-state warning. A corrupt scope file fails closed. Raw snapshot counts include structural anchors. With many exclusions, matching candidates require additional in-memory path checks; default benchmarks have no exclusions.
