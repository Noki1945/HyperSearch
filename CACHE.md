# Готовые поисковые таблицы на диске

Beta 0.1 сохраняет нормализованные имена, таблицу расположений, отсортированные ID и адаптивные posting lists в `index.fast.hsc` (или соответствующий файл economy/balanced) рядом с `index.hsi`.

При следующем запуске программа читает готовые данные вместо повторной нормализации имён, сортировки и построения списков. FRN HashMap восстанавливается из записей: память стандартного HashMap не переносится между процессами напрямую. Все файлы находятся в `%LOCALAPPDATA%\HyperSearch` либо рядом с файлом из `HYPERSEARCH_INDEX`.

## Актуальность и ошибки

* Версия формата и профиль RAM проверяются до загрузки таблиц.
* Кэш привязан к содержимому снимка: корням томов, именам, FRN/Parent FRN и признаку каталога. Одно изменение только позиции USN не требует перестроения таблиц.
* Контрольная сумма выявляет случайную порчу. Размеры, смещения UTF-8, ID, порядок exact-таблицы, списки и битовые наборы проверяются при чтении.
* Старый или повреждённый кэш перестраивается автоматически. Если сохранить его невозможно, поиск продолжает работать без дискового кэша.
* Запись — во временный файл, sync и атомарная замена. Собственные снимки, настройки, таблицы и временные файлы исключены из поиска, чтобы их сохранение не порождало бесконечную инвалидизацию.

Кэш не заменяет USN-проверку и не делает устаревший снимок актуальным. Если GUI запущен без прав доступа к журналу, это по-прежнему явно отображается в статусе. Кэширование инкрементальных изменений пока крупнозернистое: изменение состава записей перестраивает соответствующие таблицы целиком.

## Проверенный полный индекс

22 ноября 2026, Windows x64, release GNU, один сохранённый индекс C:, 1 281 006 объектов. Два отдельных процесса `profile_cache.exe`, fast:

| Измерение | Первый запуск | Повторный |
|---|---:|---:|
| Загрузка снимка и исключение служебных файлов | 553,785 мс | 531,872 мс |
| Подготовка таблиц / загрузка кэша | 2928,765 мс | 526,047 мс |
| Полная готовность библиотечного движка | 3482,551 мс | 1057,919 мс |
| Cache hit | нет | да |

Размер готовых fast-таблиц — **301 817 136 байт**, около 302 МБ. Вместе с исходным снимком около 79 МБ — примерно 381 МБ на диске. Это больше исходного списка, поскольку хранятся структуры ускорения. После загрузки таблицы всё равно занимают RAM; дисковый кэш ускоряет запуск, а не заменяет оперативную память.

Это прогретый файловый кэш Windows: настоящий холодный старт после перезагрузки и полное время появления GUI не измерены. Цифры не гарантируют ускорение на любом диске. Исходные логи: `benchmarks/cache-first.txt`, `benchmarks/cache-repeat.txt`.

Для текущего тестирования fast выбран по умолчанию в библиотеке, CLI и новом GUI. Сохранённый явный выбор пользователя другого режима сохраняется. При наличии сохранённого выбора без собственного бюджета повторный GUI-запуск пропускает повторный анализ RAM. Для собственного бюджета оценка выполняется заново перед загрузкой.
